# 验证、版本与错误定位

运行时在每步产出提交后检查本次操作和输出节点。下一轮规划前提交检查结算，明确失败时同时写入节点阻断事件。`verify_run(run_id)` 仍可对保存的执行图做独立检查。每条记录有一个目标及一个维度，状态为 `passed`、`failed`、`not_verified` 或 `not_applicable`。

| 维度 | 检查 |
| --- | --- |
| `structure` | Run 隔离、声明与交付输入、边与快照哈希、操作状态、唯一生产者和环。 |
| `current_validity` | 节点或操作涉及的版本是否仍可用于当前运行。 |
| `provenance_snapshot` | 真实检索操作生成的证据是否与保存快照一致。 |
| `source_version` | 全图检查时可配置 SourceAdapter，重新读取指定文档版本并比较哈希。 |
| `deterministic` | 通过保存的有序输入快照独立重算算术结果。自然语言结论保留 `not_verified`。 |

算术使用受控运算集合与固定的 34 位十进制上下文，使用半偶舍入。确定性检查重新计算历史操作输出，当前有效性单独报告。因此，一个计算可以在历史上通过，修订后同时标记为当前失效。

快照哈希与权威版本的匹配都不能证明内容所描述的事实。模型产出的引文没有检索记录时不能得到来源验证。用户修订内容保留版本关系，手工更正的证据保留未验证状态，重新检索可建立新的来源记录。

修订会创建新节点 ID，保留逻辑 ID 并增加修订号。旧版本标记为 `superseded`。撤销标记为 `revoked`。运行时沿消费和产出边传播 `stale`，保留历史节点、操作和验证。返回的 `InvalidationReport` 列出受影响操作和待重算节点。修订可以作为新输入重新计算，已有操作永远保留其具体输入版本。

`inspect_failure(run_id, node_id)` 返回当前状态、生成操作、实际输入、上游证据、局部验证失败和直接及递归下游。当检查只能给出候选范围时，`root_cause` 为 `unconfirmed`。

## 节点使用资格

`NodeState` 记录版本与失效状态。`get_node_usability()` 另外检查步骤结算和阻断记录。`eligible` 包含问题、快照完整的检索证据，以及输入已符合局部检查且重算通过的确定性结果。证据符合快照检查仍不等于事实已证明。`unverified` 可用于后续操作，涵盖模型假设、模型输出的最终答案和手工修订等。由未经验证的数值推导出的计算结果仍保留暂定资格。

`pending_verification` 和 `blocked` 都禁止传入执行器。明确的结构、来源或计算失败会阻断受影响的产出，后续全图审计也会沿实际依赖阻断下游。相同节点版本的阻断会保留；修复可以重新检索、重算或通过用户修订产生新节点。规划会看到失败摘要与仍可使用的输入，错误内容仍可通过历史 API 读取。重复失败受步骤、调用次数和时间预算约束。

## 跨 Run 引用检查

导入证据沿用原始来源信息。`cross_run_reference` 检查引用归属、来源版本、内容哈希、输入快照和当前可用性。导入节点仍保留原使用资格。实际执行前会重新检查输入及其导入祖先，显式全图检查也会报告已失效的引用。回放可以查看已保存的历史状态。
